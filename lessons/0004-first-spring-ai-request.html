2. The one concept: a model request is a message exchange

Your runner → ChatClient → provider-backed ChatModel → selected provider API
Provider response → ChatResponse → answer text + metadata

A system message sets the task; a user message carries the question and evidence. These are inputs to generation. ChatClient builds the exchange; ChatResponse retains the result and metadata. See Spring AI: ChatClient. We manually choose one passage here. There is no retrieval component, tool invocation, or MCP connection in this exercise.

Hint 1: request chain
ChatResponse response = client.prompt()
    .system(instructions)
    .user(questionWithEvidence)
    .call()
    .chatResponse();

Obtain the response once, then inspect that object. Calling another terminal operation on a newly built request can execute another model call.

Hint 2: response inspection

First check whether response and response.getResult() exist, then inspect:

response.getResult().getOutput().getText()
response.getResult().getMetadata().getFinishReason()
response.getMetadata().getModel()
response.getMetadata().getUsage().getPromptTokens()
response.getMetadata().getUsage().getCompletionTokens()
response.getMetadata().getUsage().getTotalTokens()

Handle unavailable metadata explicitly; do not invent token counts. See response metadata and the AssistantMessage API. Token counts measure usage, not truthfulness or answer quality.

6. Compile, predict, then execute

From the repository root, check compilation first. This does not launch Spring or call the model:

mvn -pl chat-client -am compile

Predict the answer before the first run: supplier concentration and possible production delays should be mentioned, with the passage ID; actual losses should not be asserted. Then launch the practice app once:

mvn -pl chat-client spring-boot:run

The Boot Maven plugin launches this project. The existing root run.sh still launches the financial loader and is not the launcher for this exercise. Avoid automatic live calls from tests, restart loops, or retries you add yourself.

Second deliberate run: change only the question to "How much additional long-term debt did DEMO incur because of supplier interruptions in 2024?" Keep the passage and instructions unchanged. Predict the result before executing. The evidence cannot establish an amount or a causal link. Compare the answer and token counts with the first run.

If generation is truncated, inspect the finish reason and selected model's output settings. Configure an appropriate output limit supported by that model before retrying; token-limit and reasoning parameters vary by model. A token limit is not a monetary budget.
