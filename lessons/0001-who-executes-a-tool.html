Who executes a tool?

Roadmap · Mission · Sources

Your win: trace a model's request to an ordinary Java service without giving the model responsibility for executing or authorizing it.

Start with a prediction

A user asks, "What was Apple's free cash flow in 2024?" Your repository can calculate it. How does a text-generating model get that result? Write a guess before reading on.

The boundary

The application sends messages and tool descriptions to the model. The model can return a structured request naming a tool and its arguments. Application code validates and executes that request, then returns the result to the model for a response. The model itself does not run your Java method. This is the key boundary in Spring AI's tool-calling explanation.

User: Apple's free cash flow in 2024?
  Application sends question + available tool definitions
  Model requests: getFinancialStatements(ticker="AAPL", years=2)
  Application checks arguments and permissions
  Java service supplies statement data
  Application sends tool result back to the model
  Model generates an answer using the supplied data

The name and arguments above are an illustrative future contract, not an existing method. Today, EdgarDataLoader.load() combines the services; EdgarCashFlowStatementService handles cash-flow extraction. We can first use fixtures to exercise this path without a network request.

A tool result can contain a missing value. Your application should preserve it. Asking a model to sound confident does not make an absent fact available.

Self-check after attempting

Your explanation should assign tool selection/arguments to the model request, execution to application code, and enforceable authorization to the application or service boundary. It should not treat a prompt as an access-control mechanism.
